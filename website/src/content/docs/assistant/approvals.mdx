A `write` or `control` tool doesn't run when the model calls it. The call stops, and you get an approval card. The tool runs only after you press the button.

This happens in Valet's server, not in the prompt. The model has no way to approve its own call.

<Shot id="scene/approval" alt="The chat with a card asking to pause ad blocking for 5 minutes, with Not now and Pause buttons" caption="Asked to pause Pi-hole, the assistant stops and waits." full />

## The approval card

The card says what's about to happen, in plain words. The words come from the tool, not from the model. A tool's `confirm` function can look things up, so the card can show what the service says rather than what the model typed.

<Row>
  <Shot id="scene/approval-card" label="An ordinary approval" alt="Approval card: pause ad blocking for 5 minutes; ads come back on every device until it ends" />
</Row>

**Not now** refuses, and the assistant is told so. The other button names the action: Pause, Stop, Request. One click either way. If a tool has no words of its own, the card says "Allow this:" and shows its input.

Ask something else instead of answering, and that counts as Not now: the card goes, its step reads **Skipped**, nothing runs, and the assistant is told you didn't approve it. Ask again if you still want it done.

## Dangerous actions

Some actions are hard to take back, like stopping someone's stream. Those tools set `danger`, and the button turns red. It's still one click, so read the card.

<Shot id="scene/approval-danger" alt="An approval card asking to stop Theo's stream, with a red Stop button" />

## Several changes, one approval

"Clear some space" might take three steps. The built-in `plan` tool lists them, and you approve the list once.

- You see every step and why, in order, before any of them runs.
- Each step must be a tool at a level this instance's access allows, with input that passes its own check. If one doesn't, nothing runs.
- It stops at the first failure and tells you what didn't run.
- Plans can't include the tools that edit the config.

An approved plan runs all its steps, including control tools, with that one approval. Read the list.

## Approved once, run later

A [rule](/assistant/rules/) is the one thing that acts without a fresh press. You approve it once, and it then runs its one action every time its trigger goes off.

- Its card names the trigger from the card's real title and the action in the action tool's own words, the same words that tool's own approval would show. The model's message is shown in quotes.
- A rule can only run one integration tool. Never the config, Valet's own tools, plans, pins or MCP.
- Every run is checked again against `assistant.access` as it is then, against the tool's own input check, and against whether Valet may act. Lower the access and the rule stops.

So approving a rule is approving that action for as long as the rule stands. Remove it from the `valet.rules` card or by asking.

## After you approve

<Shot id="scene/after-approval" alt="The chat after approval, showing Paused ad blocking and a short answer" caption="The step shows in the chat, and the answer says what happened." full />

If the tool fails, the chat says so, and the failure goes in the log.

## The activity log

Everything that isn't a read goes in `data/activity.json`: who asked, how, what it did, and whether it worked. Secrets are redacted before it's stored. It keeps the last 2,000 entries.

That covers changes from chat, plans, rules, the page's own buttons, and pins. A rule's entry says it was a rule. From MCP servers the assistant uses, only tools that needed approval are logged. Every call an outside client makes to [Valet's own MCP server](/assistant/mcp/#valet-as-an-mcp-server) is logged, reads included.

Put `valet.activity` in your layout to see it on the page, or ask "what did you change?". The `activity_log` tool answers that, so you can check what it did by asking.

## Undo

A tool can name the tool that reverses it. qBittorrent's `pause_downloads` and `resume_downloads` name each other. When one has run, the activity card offers an **Undo** button for the latest entry that can be undone.

Most tools have no undo. Removing a torrent or stopping a stream can't be taken back, so check the card before you approve.

## What approval doesn't do

An approval means you saw a sentence and pressed a button. It doesn't check the sentence is wise.

- The card shows the tool's input. If the model picked the wrong film or the wrong service, the card shows the wrong one, and you need to catch it.
- A tool without `confirm` shows its raw input, which is harder to read.
- If you approve everything without reading, you've given the assistant control. Use `read` for anything you wouldn't check.
- MCP tools' cards can only show their input, since Valet doesn't know what they do. See [MCP](/assistant/mcp/).

## How it holds

An approval is signed by the server when it's asked for and checked when it comes back, against the tool and its input, so a request can't claim one. A plan's card shows each step in the tool's own words, and a step that names something vague is refused rather than guessed at. Signatures last until Valet restarts, so a card left open across a restart has to be asked again.
