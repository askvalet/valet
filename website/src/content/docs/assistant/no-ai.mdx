title: Running with no AI
description: Leave out the assistant block and the page loses nothing.

---

Valet is a homepage first. The assistant is optional, and leaving it out takes nothing from the page.

```yaml title="config.yaml"
# no assistant: block
title: Home
integrations:
  downloads:
    type: qbittorrent
    url: http://qbittorrent:8080
    username: ${QBIT_USER}
    password: ${QBIT_PASS}
layout:
  - widgets: [downloads.active]
```

That's the whole setup. There's no switch to turn off.

## What stays

- Every card, widget and integration.
- Every button and control, when [sign-in](/start/sign-in/) allows them.
- The palette, for finding services, running actions and typing [commands](#commands).
- Live rings, notices, and [notifications](/reference/configuration/#notify) from `live.notify`.
- The year in review. No model writes it.
- History graphs on tiles.

The AI SDK and the MCP client load on the first question. With no assistant, they never load, so they cost no memory.

## Commands

Type a plain command in the palette and it runs straight away, with no model: "pause downloads", "lights off", "what's playing", "pause ads 10 min". Integrations bring their own; there's nothing to set up.

With no assistant, commands do what the page can already do: its actions (when [sign-in](/start/sign-in/) allows them) and tools that only look, which show their card in the palette. Anything that would need a tool to add or change something waits for an assistant, and then follows `assistant.access` like the chat does, approval card included. On a read-only page commands only look. Nothing on this path ever calls a model, with an assistant or without.

## Search inside your services

As you type in the palette, Valet also searches the services that can be searched: documents, saved links, the library, photos, games, recipes, feeds, the calendar and the house. Each has its own group, and its rows arrive as it answers, so a slow service never holds up a fast one. A row with an address opens it. One without, like a light or a show in the library, shows the service's card right there, switches included.

No model is involved. With an assistant, `access: none` for an integration takes it out of the search as well. `find: false` in the config turns the search off, and `find: [docs, bookmarks]` keeps it to those.

## What goes

- The chat, and its button on the page. The ask box becomes a search box.
- The summary when you hover the status sentence.
- Tools, plans, reminders and pins, which all live in the chat.
- [Rules](/assistant/rules/). No model runs them, but what they may do comes from `assistant.access`, so without it they pause.
- [MCP servers](/assistant/mcp/) under `mcp:`, which only the assistant uses. Valet's own MCP server, `mcpServer`, works without one.

`hero.search: false` removes the box as well.

## In between

You can keep the chat and turn off everything it does on its own:

```yaml title="config.yaml"
assistant:
  baseURL: http://ollama:11434/v1
  model: qwen3:8b
  background: { watch: false, brief: false, suggest: false }
chat:
  suggestions: fixed    # your list, with no model calls
  overview: false       # no ask box on the overview
```

Now the model runs only when you ask it something. With `read` access, the default, it still can't change anything.
