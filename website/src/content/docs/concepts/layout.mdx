`layout:` is a list of sections, top to bottom. Each section holds widgets and says how to draw them. The full list of options is in the [reference](/reference/configuration/#layout).

```yaml
layout:
  - title: Now
    columns: 2
    widgets: [plex.streams, downloads.active]
  - title: Services
    variant: minimal
    header: false
    favorites: [Plex, Home Assistant]
    widgets: [services.status]
```

## Display

`display` picks how a section draws its widgets.

| Value | What you get |
|---|---|
| `cards` | Full cards. The default. |
| `tiles` | Headline tiles with live graphs, and the card's buttons and switches. |
| `rings` | The same headlines as ring gauges, coloured by health. |
| `media` | Every item of the section's media cards as artwork tiles in one grid. |

Tiles and rings use a card's `summary` or `summaries`. A card without one gets a headline from what it holds:

| Card | Its tile |
|---|---|
| Status | All up, or how many are down and which, with a bar for each service |
| List, links | How many, and the first one |
| Shelf, media, photos | How many, the first one, and its picture |
| Ranked | The top one, and its picture |
| Controls | How many switches are on, or the first reading (Locked, Home) |
| Calendar | The next event, and when |
| Schedule | The next time |
| Weather | The temperature now, the sky, the high and low |
| Chart | The latest value, over its graph |
| Stats, key and value, table | The first number or row |

A card with nothing short to say, like text or a camera, has no tile.

### Opening a tile

Tap a tile, or press Enter on it, and its full card opens in a sheet over the page: everything the card shows, and everything it can do, by the same rules as the card itself. Escape, or a tap outside, closes it.

Nothing to set up: every tile opens its own card. Two settings change that:

```yaml
- title: Glance
  display: tiles
  widgets:
    - { widget: home.lights, open: home.plan }   # this tile opens the house instead of its own card
    - { widget: weather.now, open: false }       # this one is only to look at
```

`open: false` on the section keeps all its tiles to look at. A tile set to open a widget the person can't see opens its own card instead.

### Pressing a tile

A tile carries what its full card can do: the card's buttons, its banner's button, and its switches, which light up while they're on. Pressing one does just that; it doesn't open the card. Its link moves to a small corner button. Nothing to press shows on a read-only page or to someone whose profile can't use the card, and on the [wall display](/concepts/wall/) only for cards on `wall.touch`. Every press is in the activity log, as it is from the card.

## How cards are arranged

With no other instructions, Valet picks an arrangement from what's in the section:

- **Any widget has a size other than medium.** A [bento grid](/concepts/sizes/) of 2, 4 or 6 columns. Rows end flush.
- **`columns` is set.** That many cards per row, from tablet width up. A number is 1 to 4. For per-screen control, use an object, up to 8: `{ phone: 1, tablet: 2, desktop: 3, wide: 4 }`. `wide` is a page wider than 1760px, and keeps the `desktop` count when you leave it out. In that grid, a widget's own `cols` and `rows` span more than one column or row.
- **A card marks itself wide.** It takes two thirds, and the rest stack beside it, unless `columns` is set.
- **More than three cards.** They pack into columns, with compact rows.
- **Otherwise.** They share a row and a height.

`gap` sets the pixels between a section's cards. `tabColumns` sets different columns on the section's own tab.

A section without a heading carries on the grid above it, with the cards' gap between them rather than a section's. That lets you build a dense page from rows of different shapes:

```yaml
- heading: false
  columns: { phone: 1, tablet: 3, desktop: 3 }
  widgets:
    - { widget: dns.stats, cols: 2 }      # two thirds
    - drives.drives                        # a third
- heading: false
  columns: { phone: 1, tablet: 3, desktop: 3 }
  widgets:
    - plex.streams
    - { widget: photos.memories, cols: 2, rows: 2 }   # two thirds, two rows tall
    - downloads.active                     # under what's playing
```

## Density and titles

| Option | What it does |
|---|---|
| `variant: minimal` | Tighter rows with the essentials. For a status card: icon, name, dot. |
| `header: false` | Cards in the section drop their title bar, on the overview and on its tab. |
| `heading: false` | No title above the section. It still names its tab. |

## Favourites

A long status card can show only what matters on the overview:

```yaml
- title: Services
  favorites: [Plex, Home Assistant, Immich]
  widgets: [services.status]
```

It shows those names, and whatever's down, with a link to the whole list on the section's tab.

## Sidebars

`place: left` or `place: right` makes a section a sidebar on wide screens. `columns` then sets how many columns its list uses. Sizes don't apply in a sidebar.

```yaml
- title: Services
  place: right
  variant: minimal
  widgets: [services.status]
```

## The hero

The top of the overview: the title, a status line, the ask box. `hero:` controls each part.

```yaml
greeting: Sam
hero: { greeting: "Welcome back, {name}", align: left, review: false }
```

`align: left` puts the greeting at the top left, level with the top bar, which leaves more of the screen for cards. Each tab then shows its own name in the same place, so every screen starts the same way.

The title is "Sam's homelab" until you say otherwise. `hero.greeting` replaces it: `{name}` is your `greeting`, and `{greeting}` is the time of day, as in `"{greeting}, {name}"`.

`status` is one sentence under the title, two things at most: "All 30 services are running and Sam is watching Dune." or "Everything's running except Mealie." What needs someone comes first, and services off by choice aren't counted. With an assistant, hover it for the brief.

For a denser page, `hero: { greeting: false }` drops the title, and adding `status: false` and `search: false` drops the summary line and the ask box too. `search` is the ask box, or a search box when there's no assistant. `review` is the year in review link, on its own line under the suggested questions. You can dismiss it for the visit. `review: end` also closes the overview with a card, and `false` drops both.

## The menubar

Small rings in the top bar, one for each headline number. Hover one for its live graph.

```yaml
menubar: [system.tiles, dns.stats]
weather: weather.now      # a ring beside the clock
calendar: family.agenda   # events when you hover the clock
```

Use the object form for more: `position`, `labels`, `clock`, `date`, `theme` and `size`.

## Live activities

What's playing, what's downloading, the vacuum, an event in progress. They're rings in the top bar, in the same plate as the menubar's, to their left with a thin divider. Artwork inside, progress around.

Hover or tap one for the story, like every other ring. On phones they share the top row, up to two of them, and the clock steps aside to make room. When nothing is live, they're not there.

<Shot id="scene/ring-open" label="A ring opened" alt="A ring in the top bar with its popover open, showing what's playing and how far along it is." />

```yaml
live:
  activities: [plex.streams, downloads.active, home.house]
  notify:
    - { widget: downloads.active, on: end, text: "{title} finished downloading" }
    - { widget: services.status, on: down, push: true }
```

List widgets in order of importance. `notify` shows a short toast at the bottom of the page on `start`, `end`, `down` or `up`, and the widget must be placed on the page. `push: true` also sends it to your [notification channels](/recipes/#notifications).

## Meetings

A calendar knows an online meeting by its link: Google Meet, Zoom, Microsoft Teams, Webex, Whereby, Jitsi, GoTo and a few more. Ten minutes before one, the calendar's ring appears and counts down, "in 4m", then "Now · 20m left". Tap it for who it's with and a **Join** button. If two overlap, the one on now leads and the ring says "+1".

<Shot id="scene/meeting-ring" label="A meeting about to start" alt="The calendar's ring in the top bar counting down to a meeting, its popover open with the time, who it's with and a Join button." />

A minute before, Valet sends a reminder with the meeting's name and time to your [notification channels](/recipes/#notifications) and to every device that turned on notifications in ⌘K. Tapping it on the device opens the meeting. Each reminder is sent once, even across a restart.

In the agenda, a meeting's row shows the service and a small Join button. In the week, a meeting has a small Join button on its block, and tapping any event shows its time, place, calendar and Join over the week. ⌘K has **join meeting** and **next meeting**, and you can ask the assistant "what's my next meeting?".

<Shot id="scene/calendar-week" label="The week" alt="The calendar card a third of a row wide: three days side by side with the hours down the side, today shaded with a line at the time now, events as blocks in their calendar's colour, and a meeting's block with its Join button." />

```yaml
integrations:
  work:
    type: calendar
    calendars: ["${GOOGLE_ICAL_URL}"]   # Google Calendar: your calendar's settings, Secret address in iCal format
    meetings: { remind: [10m, 1m], me: you@example.com }
live:
  activities: [work.agenda]
```

It works with no `meetings:` at all. Put the calendar's widget in `live.activities` for the ring. `me` leaves out what you declined; `meetings: false` turns it off. The [calendar page](/integrations/calendar/) has the rest.

## The palette

Ctrl+K (⌘K on a Mac) opens search and actions from anywhere. Typing a plain command, like "pause downloads" or "lights off", runs it with no model: see [commands](/assistant/no-ai/#commands). Set `search:` to add web search.

Plain commands come first, and need no model: "pause downloads", "lights off", "what's playing", "pause ads 10 min", "stop plex". Typed exactly, Enter runs one at once. Something that only looks shows its card right there, and anything that changes something shows its approval card first, the same one the chat uses. A command still being typed is offered below Ask, and two that match the same words are both shown, so Enter never guesses. When nothing matches, Enter asks the assistant. Each integration's page lists its commands under the tools, and [running with no AI](/assistant/no-ai/#commands) says what they may do.

Valet's own docs come last, under a **Docs** heading: type "wallpaper" or "backups" and the pages and sections about it are there, and an integration's name, like "sonarr", offers its page beside the service. "docs" or "help" alone offers the main pages. Valet searches the copy of the docs it ships, so this works offline; picking one opens it on askvalet.dev in a new tab.

<Shot id="scene/palette" full alt="The command palette over a blurred page: quick actions first, such as pausing Pi-hole, then services to open." />

It also searches inside your services as you type: documents, saved links, the library, photos, recipes, the calendar. Each service answers under its own name as it's ready, through the same search tools the assistant has, so a profile or an integration the assistant can't read is left out. `find: false` turns this off, and `find: [paperless, karakeep]` keeps it to those.

<Shot id="scene/palette-find" full alt="The command palette with “inter” typed: a suggestion and Ask first, then a film from the library, Interstellar, 2014, with its poster, under the service's name." />

```yaml
search: duckduckgo   # also google, kagi, brave, startpage, searxng, or a URL with {q}
```
